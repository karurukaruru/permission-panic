# Permission Panic 发布安排

## 我的建议

先发 X 英文实机视频，同日再发 Threads（脆）繁体中文版本。
这是根据项目的英文界面、AI 编程主题和现有素材做的内容判断；没有你的账号受众数据，不能保证哪个平台曝光更高。
如果你的脆账号已经有稳定互动，也可以把脆放在第一位，复用同一段视频。

第一波只让人做一件事：点开试玩，完成 10 关，回帖晒成绩。
GitHub 放在后续回复，给想看源码的人；首帖优先放试玩链接。
不要同时堆“求 Star、求转发、求关注”等多个诉求。

## 可以直接执行的顺序

1. X 首帖：使用 `launch-copy.md` 的英文主帖，附 `gameplay.mp4` 和试玩链接。视频是实际操作剪辑，事故均为模拟。
2. 自己的第一条回复：补仓库链接，并问「哪一关让你犹豫最久？」。
3. 同日在脆发繁体稿，附同一视频。文案强调「你会不会顺手按允许」，请玩家回帖晒成绩卡。
4. 收到第一批反馈后，记录误解最多的题目，先修正歧义；后续分享真实反馈和改动，不编造用户量。
5. 再考虑开发者社区。先看对应社区当前自荐规则，针对题目设计征求反馈，不复制粘贴刷屏。

## 素材选择

| 场景 | 素材 | 配文重点 |
| --- | --- | --- |
| 首次发帖 | `gameplay.mp4` | npm test 的模拟反转、挑战 1000 分 |
| 链接预览 | `launch.png` | Allow 键概念图，已加入网页分享元数据 |
| 无法上传视频时 | `twist.png` | 明确是游戏中的模拟事故 |
| 玩家反馈 | 玩家自行分享的成绩卡 | 只使用取得许可的反馈和图像 |

12 秒视频结尾的 800 分、90% 正确率属于素材中的实际操作结果；它不是用户平均成绩，也不是连续通关录像。
海报是概念视觉；界面截图与视频才是实际游戏画面。

## 发布时的检查

打开试玩链接，确认手机能玩；首帖带真实链接，保留“模拟”说明。
视频不需要解说，原有英文画面能解释操作。中文稿负责补上下文。
图片替代文字可用：「Permission Panic 宣传概念图：一颗悬浮的 Allow 键，文案为 Your agent asks. You decide.」。

X 官方支持上传视频，也可把后续内容接成串文；Threads 官方说明支持文字、链接、图片和视频。
这些是格式能力，不是流量保证。参考：[X 视频说明](https://help.x.com/en/using-x/x-videos)、[Meta Threads 介绍](https://about.fb.com/news/2023/07/introducing-threads-new-app-text-sharing/)。

本次只准备文案与素材，没有向任何社交账号发帖。
